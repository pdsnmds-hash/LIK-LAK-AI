# LIK LAK AI Sandbox

Нативный Android-проект на Kotlin и Jetpack Compose по предоставленному пакету `LIK_LAK_AI_Sandbox`. Package/applicationId: `bg.liklak.sandbox`. Android 8.0+ (minSdk 26), targetSdk 36, compileSdk 37.

Реализованы каталог 36 кейсов (12 экспериментов и 24 читательских сценария), совместные фильтры и поиск по содержимому и библиотекам, подробности с пятью разделами, работающие локальные эксперименты с граничными вариантами, справочник 9 интеграций, локальная библиотека кейсов/кода/конфигураций и контакты LIK LAK EOOD. BG при первом запуске, EN по выбору; системная, тёмная и светлая темы. Терминальная палитра сохранена из референса.

Локальные алгоритмы выполняются в Kotlin. Python и prompts — справочный материал. В приложении нет модели, сетевых API-вызовов, разрешений, аналитики, аккаунтов и ключей. OCR-кейс извлекает поля из уже распознанного текста. При открытии почты пользователь сначала выбирает возможности и видит редактируемый текст. Отправка выполняется во внешнем почтовом приложении самим пользователем.

## Подробный решебник — первый этап


Добавлены 13 офлайн-руководств на BG/EN: вводная основа и 12 отдельных кейсов, всего 117 разделов. В каждом кейсе — постановка задачи, контракт данных, прохождение эксперимента, запускаемый Python-рецепт, объяснение кода, развитие до AI-интеграции, диагностика, проверка качества и упражнение с раскрываемым решением.

В кейсе кнопка **«Прочетете ръководството» / “Read the guide”** находится в обзоре. В «Инструменти» доступны вводная глава и весь решебник. Экран чтения имеет оглавление с переходами, поиск по объяснениям/коду/решениям, копирование, перенос кода и отдельное раскрытие ответов. Поиск каталога также находит материал внутри новых руководств.

13 локальных Python-рецептов реально исполнены; полученный JSON включён в документацию. Пример HTTP-запроса к модели — отдельная неисполненная интеграционная инструкция. Python из руководств запускается на компьютере и не исполняется Android-приложением. Расширенные рецепты явно отделены от текущей логики экспериментов.

Тот же материал доступен для компьютера в [docs/handbook/bg](docs/handbook/bg) и [docs/handbook/en](docs/handbook/en). Для изменения текстов редактируйте `scripts/handbook_content.py`, затем выполняйте `python3 scripts/build_handbook.py`: он проверит локальные рецепты, пересоберёт assets и Markdown. Отчёт об обновлении: [docs/HANDBOOK.md](docs/HANDBOOK.md).

## Открытие и сборка

Откройте корень проекта в Android Studio. Нужны JDK 17+, Android SDK Platform 37 и Build Tools 36.0.0. Укажите SDK в `local.properties` или `ANDROID_HOME`. Gradle Wrapper включён; первому запуску требуется доступ к репозиториям зависимостей.

```sh
./gradlew testDebugUnitTest assembleDebug
```

APK после успешной сборки: `app/build/outputs/apk/debug/app-debug.apk`.

На macOS доступен `scripts/build.sh testDebugUnitTest assembleDebug`: он использует JBR Android Studio и отдельный `.gradle-home` внутри проекта. На устройстве/эмуляторе запустите `./gradlew connectedDebugAndroidTest` для проверки сохранения Room, языка DataStore и отмены/сброса.

**APK собран и запущен на эмуляторе `LIK_LAK_API36` (Android 16 / API 36, Pixel 8).** Команда `testDebugUnitTest assembleDebug` завершилась успешно: 26 JVM-тестов прошли, Room/KSP и ресурсы собраны. APK: `app/build/outputs/apk/debug/app-debug.apk`; копия — `dist/LIK-LAK-AI-Sandbox-debug.apk`.

Приложение открывается без AndroidRuntime-ошибок. Сохранены реальные скриншоты в `docs/screenshots/`. Полная проверка всех размеров, TalkBack и process death ещё не проведена.

Первоначальные ограничения сокетов сняты после предоставления доступа. Ранний отчёт в `docs/ACCEPTANCE.md` сохранён как история; проверка первого запуска — `docs/EMULATOR.md`, обновление решебника — `docs/HANDBOOK.md`; актуальный пользовательский импорт — `docs/ENRICHMENT.md`.

Команды выполненных проверок:

```sh
python3 scripts/validate.py
python3 scripts/check_kotlin.py

```

Команда `check_kotlin.py` — диагностическая проверка для этой машины: использует локальный Maven-кэш и Android SDK, выбирает доступные runtime-артефакты; это не воспроизводимая замена Gradle. Все production-зависимости зафиксированы в Gradle-файлах.

Полный отчёт: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). Логи: [Kotlin/JUnit](docs/kotlin-check.log), [контент](docs/content-check.log), [Gradle](docs/build.log).

## Структура

- `app/src/main/java/bg/liklak/sandbox/` — Compose UI, ViewModel/StateFlow, алгоритмы, Room и DataStore.
- `app/src/main/assets/` — полные структуры BG/EN кейсов, код, prompts и справочник.
- `app/src/test/` — выполненные целевые проверки алгоритмов и контента.
- `app/src/androidTest/` — выполненные проверки Room, DataStore и отмены/сброса на устройстве.
- `docs/handbook/` — те же руководства на BG/EN в Markdown.
- `reference/` — исходный пакет без изменений.
- `scripts/content.py`, `scripts/sources.py` — воспроизводимая сборка локального контента. Переводы BG/EN написаны в этих файлах.

Материалы интеграций описывают настройку отдельно от приложения; они не подтверждают готовую production-интеграцию или AI-портфолио компании. Цена, сроки и технический объём обсуждаются отдельно.
